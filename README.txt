v23 修正版

- 修复 Cloudflare Workers Free 创建用户时可能出现的 JSON / HTML 错误。
- 用户密码仍使用 PBKDF2-SHA256 + 独立随机盐保存。
- 针对 Workers Free 每次请求 10ms CPU 限制，将新账号默认 PBKDF2 迭代次数调整为 20,000。
- 用户账号、权限、操作日志、系统设置、备份恢复等 v22 功能全部保留。

沙巴光伏自备电厂内部业务系统 v22｜用户账号 + 权限 + Audit Log + 系统设置

本版基于 v21，保留原有 Cloudflare KV 数据和功能，并新增：

1. 用户账号登录
- 不再使用全员共用 SITE_PASSWORD。
- 登录页改为“用户名 + 密码”。
- 系统管理员账号固定为：admin
- admin 的密码继续使用 Cloudflare Secret：ADMIN_PASSWORD。
- 管理员在“管理后台 → 用户账号”创建普通员工账号。
- 普通账号不会显示“管理后台”，并且服务器端 API 也会拒绝普通用户访问后台接口。
- 可编辑显示名称、重设密码、停用 / 启用账号、删除账号。
- 密码不会明文存入 KV，使用 PBKDF2-SHA256 + 独立随机盐保存哈希。
- 账号被停用后，后续 API 请求会立即失效并要求重新登录。

2. 30 分钟无操作退出继续保留
- 网站 30 分钟无操作自动退出。
- 管理员也是同样规则。
- 关闭浏览器标签页后重新打开，需要重新登录。
- 现在管理员不再进入网站后再输入第二次后台密码；admin 账号本身就是管理员身份。

3. 权限管理
- admin：系统管理员，可看见并进入管理后台。
- 管理员创建的账号：普通用户，只能使用业务网站，看不到管理后台。
- 普通用户即使手动调用后台 API，也会返回“没有管理员权限”。

4. 操作日志 / Audit Log
- 最多保留最近 500 条。
- 记录成功登录。
- 记录共享公告修改。
- 记录主页模块 / 内部按钮 / 月计划 / 花名册 / 系统设置 / 用户账号 / 备份与恢复等管理员操作。
- 日志显示：时间、账号、权限、操作、对象。

5. 系统设置
管理后台可修改：
- 系统名称
- 系统副标题
- 顶部页面标题
- 顶部页面说明
- 主页标题
- 主页说明
- 主页右侧标签
- 页脚文字
保存后前台会同步更新；登录页也会读取系统名称与副标题。

6. 完整数据备份
v21 备份功能继续保留。
完整备份会包含 SHARED_BOARD KV 中全部数据，包括：
- 普通用户账号（仅密码哈希，不是明文密码）
- 系统设置
- Audit Log
- 花名册
- 主页模块
- 内部按钮
- 月计划
- 共享公告及历史
- 其他 KV 网站数据

ADMIN_PASSWORD 是 Cloudflare Secret，不会包含在备份中。
以后恢复备份后，普通用户账号也可以一起恢复；只需要重新配置 Cloudflare 的 ADMIN_PASSWORD。

部署：
把 public、src、wrangler.jsonc、README.txt 上传到原 GitHub 仓库并 Commit。
Cloudflare 会按现有 Worker / KV 配置自动部署。
不需要新建 KV，也不要删除 SHARED_BOARD 绑定。

升级后的第一次登录：
用户名：admin
密码：你目前 Cloudflare Variables and Secrets 中的 ADMIN_PASSWORD

登录后：管理后台 → 用户账号 → 创建员工账号。

旧的 SITE_PASSWORD：
v22 已不再使用 SITE_PASSWORD。Cloudflare 里即使还保留这个 Secret 也不会影响网站；可以暂时留着。


=== v24 更新 ===
1. 普通用户和创建出来的管理员可在右上角“修改密码”中自行修改自己的密码。
2. 修改密码需要先输入当前密码，成功后自动退出并要求使用新密码重新登录。
3. 创建/编辑用户时可选择“普通用户”或“管理员”。普通用户看不到管理后台，管理员可进入后台。
4. 内置 admin 账号继续使用 Cloudflare 的 ADMIN_PASSWORD Secret；其密码不能在网站里直接修改。
5. 用户角色变化后，原登录会话会要求重新登录，以应用新的权限。
